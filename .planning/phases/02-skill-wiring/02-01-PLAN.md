review-tier.sh (scripts/gsd/review-tier.sh — frozen lever):
  Usage: review-tier.sh [--staged | --all | --file <path>]
    --staged (default) -> git diff --staged; if empty, git diff HEAD
    --all              -> git diff <base>...HEAD ; base = $REVIEW_TIER_BASE (default main)
    --file <path>      -> git diff -- <path>
  Env: REVIEW_TIER={light|standard|full} overrides (reason "override"); other values ignored.
       REVIEW_TIER_BASE (default main) for --all.
  stdout: exactly one line "<tier> <reason>" (tier in {light,standard,full}); fail-safe prints
    "standard fail-safe" and exits 0 on any git-metadata failure.
  stderr: all warnings; exit 0 on any classification (incl. fail-safe standard), 2 on usage error.
  Mode parity: review-gate's DIFF_TARGET is `--staged` (default) / `main` (--all) / `--file*`.
    Pin `REVIEW_TIER_BASE=main` on the --all call so review-tier's base matches the gate's
    hardcoded `main...HEAD` — otherwise a differing env base tiers a different diff than is reviewed.

adversary-host.sh (scripts/gsd/adversary-host.sh — frozen lib, FULL tier only):
  Sourceable. `detect_orchestrator_host` -> claude|codex ; `adversary_kind_for_host <host>` -> opposite ;
  `adversary_invoke <kind> <timeout> <model> <effort> <prompt>` runs the opposite CLI. codex arm pins
  `sandbox_mode="read-only"`; claude arm runs `-p` non-interactive (tool prompts auto-deny). rc=127 if
  the bin is absent (fail-soft). FULL reuses THIS lib for its extra adversary — do not hand-roll an
  unsandboxed reviewer against attacker-influenceable diff/prompt text.

findings-queue (lib/gates.py — frozen; CLI arm at lib/gates.py:1071):
  python3 "$GATES_PY" findings-queue add <file> <issue>   -> prints {"sig","deduped"}; exit 0/2(usage)
  python3 "$GATES_PY" findings-queue list [--unresolved]   -> prints JSON array; exit 0
  python3 "$GATES_PY" findings-queue resolve <sig>          -> exit 0 ok / 1 unknown sig / 2 usage / 3 schema
  Semantics that force the dedup design:
    - `add` returns deduped:true for ANY existing sig, resolved OR unresolved — so `deduped` from add is
      NOT the required count. It also never re-appends (one entry) and never un-resolves an entry.
    - `list --unresolved` EXCLUDES resolved records — it CANNOT enumerate resolved sigs. Use full `list`.
    - Signature = full sha256 over structured [file, normalized_issue]; a reworded issue on the same file
      yields a distinct signature (EDGE-004: exact-normalized, not fuzzy).
  Store = $GATES_STORE (default .feature-fix-swarm/evidence.json, RELATIVE) — the SAME store preflight/grant
    use. Resolving REPO_ROOT does NOT canonicalize a relative store; run every call from $REPO_ROOT so it
    resolves once.

GATES_PY resolution — CAPABILITY PROBE (NOT the first-exists loop; a workspace has an installed
  ~/.claude copy that lacks findings-queue and would win first-exists):
  REPO_ROOT="$(git rev-parse --show-toplevel 2>/dev/null || pwd)"
  GATES_PY=""
  for candidate in \
    "$REPO_ROOT/packages/feature-fix-swarm/lib/gates.py" \
    "$HOME/.claude/lib/feature-fix-swarm/gates.py" \
    "$REPO_ROOT/lib/gates.py"; do
    [ -f "$candidate" ] || continue
    if python3 "$candidate" findings-queue list >/dev/null 2>&1; then GATES_PY="$candidate"; break; fi
  done
  # none support findings-queue -> WARN "findings persistence unavailable", DEGRADED_PERSISTENCE=1,
  # skip recording, NEVER block the verdict.
