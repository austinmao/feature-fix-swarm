<feature>
  <name>consent-check.sh — fail-closed capability/consent assertion</name>
  <files>scripts/gsd/consent-check.sh, tests/consent-check.bats</files>
  <behavior>
    Contract (REQ-01), exhaustively:
    - `consent-check.sh <capability-id>` with exactly one arg: queries
      `node "$REPO_ROOT/node_modules/.bin/gsd-tools" capability list` (JSON array of
      entries with `id` and `status` fields, verified shape per 01-RESEARCH.md Sources).
    - Exit 0 iff an entry with `id === <capability-id>` exists AND its `status === "active"`.
    - Exit 1 with actionable stderr in every other verification outcome: id absent,
      id present but status not "active", node not on PATH, gsd-tools binary missing,
      gsd-tools non-zero exit, empty stdout, or unparsable JSON. Fail-closed: no path
      through the script may reach exit 0 without a positive parse-and-match.
    - Exit 2 with `usage: consent-check.sh <capability-id>` on stderr when arg count != 1.
    - `REPO_ROOT` resolution: `${CONSENT_CHECK_REPO_ROOT:-$(git rev-parse --show-toplevel 2>/dev/null || pwd)}`.
  </behavior>
  <implementation>
    Copy 01-PATTERNS.md Pattern 1 (fail-closed dependency checks) + Pattern 2
    (JSON-argv handoff to node -e) verbatim, adapted only for the
    CONSENT_CHECK_REPO_ROOT override. House style: `#!/usr/bin/env bash`,
    `set -uo pipefail` (no -e), bash-3.2-safe, all expansions double-quoted.
  </implementation>
</feature>
