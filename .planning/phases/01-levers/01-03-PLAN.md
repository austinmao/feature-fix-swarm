<objective>
Build `scripts/gsd/liveness-check.sh`: a composite AND-of-death autonomous-run liveness
detector. It reports ALIVE (exit 0) if ANY of three signals holds — process alive, recent
activity (state-dir mtime within a window), or an in-flight granted ship action — and DEAD
(exit 1) only when ALL THREE fail, so one transient failed probe never kills an overnight
wave (US8).

Purpose: FFS today declares runs dead on single-signal probes; adopt-wip needs a resilient
composite check before abandoning WIP (RESEARCH Architectural Responsibility Map).

Output: liveness-check.sh + its 8-row truth-table bats coverage.

discrepancy): plan.md references a `scripts/gsd/run_state/` convention that DOES NOT EXIST;
the repo's `lib/run_state/` is an unrelated SQLite CLI with no pid column (RESEARCH
Discrepancy 2 + Pitfall 1). This lever therefore INVENTS a self-contained contract, per
RESEARCH Open Question 3 recommendation:
  `liveness-check.sh <pidfile> <state-dir> [--run-id ID] [--window-min N]`
window default 30 (LIVENESS_WINDOW_MIN env fallback). The ship-grant signal reuses the
existing GATES_PY resolution + RUN_ID derivation from review-gate-command.sh — it does NOT
invent a new path scheme. Bats fixtures freely mock the pidfile/state-dir (no other lever
needed first — Phase 1 no-cross-deps).
</objective>
