<objective>
Add a `findings-queue add|list|resolve` subcommand family to `lib/gates.py` that
persists review findings — each keyed by a stable full-sha256 signature over a
structured `json.dumps([file, normalized_issue])` encoding — under a `findings` key in
the existing evidence store, so fix rounds get the complete queue and re-runs skip
already-resolved signatures instead of re-litigating them (US4). Additive only: it
reuses gates.py's own store lock + atomic write and never touches
`verify_done`/`run_gate` exit-code semantics.

Purpose: a second findings store would violate single-authority (plan.md, explicit). The
store already namespaces unrelated state under `_autonomy`; `findings` is one more
top-level namespace on the same file (RESEARCH Pattern 3) — with a shape guard, because
existing gate records use unrestricted task IDs as top-level keys and a prior task named
`findings` must produce a clear error, never a clobber.

Output: the three functions + one CLI dispatch arm in lib/gates.py, and its pytest
coverage (function-level + full subprocess PATH-004 lifecycle, signature encoding,
dedup atomicity, unknown-sig error, schema guard, isolation, real concurrency).
</objective>
