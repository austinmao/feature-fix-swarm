<objective>
Extract the security-surface keyword pattern into one sourceable home
(`scripts/gsd/security-surface.sh`), rewire `security-model-fence.sh` to source it with
zero behavior change, and build `scripts/gsd/review-tier.sh`: a diff risk-tier detector
emitting `light|standard|full` + reason so review-gate can size its pipeline to the
diff's risk (US3). Logic lives in a testable lever, not skill prose (plan.md explicit).

Purpose: a 2-file docs diff should not pay the same review cost as a 40-file auth change;
AC-004 also requires the security-surface list have a single source of truth shared with
the fence.

Output: security-surface.sh (new), the one-line fence rewire, review-tier.sh (new), and
review-tier.bats.

RESOLVED DESIGN DECISION (Open Question 2 — what "security-surface path" means): review-tier
FULL trigger matches CHANGED FILE PATHS (`git diff --name-only <base>`) against the shared
keyword pattern (case-insensitive), NOT diff CONTENT. RESEARCH Open Question 2 + Anti-Pattern
"Path-content confusion" recommend this: it is cheaper (no diff-content scan) and matches the
spec PATH-003 "2-file auth-touching" fixture most naturally (a file pathed around auth, e.g.
`lib/auth/session.py`). The fence keeps its CONTENT-grep mode unchanged; review-tier uses the
same pattern in PATH mode — but with path-component/token boundaries so `docs/authoring.md`
does NOT match `auth` (finding 11). review-tier classifies the SAME diff review-gate reviews via
mode flags mirroring the gate's DIFF_TARGET (`--staged` default / `--all` / `--file`); see the
API contract in <interfaces>.
</objective>

review-tier.sh API CONTRACT (pinned — Phase 2 wires against THIS; finding 6):
  Usage: review-tier.sh [--staged | --all | --file <path>]
  Diff modes MIRROR review-gate's DIFF_TARGET (SKILL.md:100-118) so the tier
  classifies the SAME bytes the gate reviews:
    --staged  (DEFAULT) -> git diff --staged ; if empty -> git diff HEAD
    --all               -> git diff <base>...HEAD   (three-dot = merge-base)
    --file <path>       -> git diff -- <path>        (single path)
  Base for --all: env REVIEW_TIER_BASE (default `main`), same literal review-gate uses.
  Override:  env REVIEW_TIER in {light,standard,full} -> that tier, reason `override`.
             Any other REVIEW_TIER value is ignored (falls through to auto-detect).
  Base resolution (option-injection safe): git rev-parse --verify --end-of-options
    "${REVIEW_TIER_BASE}^{commit}" — pass ONLY the resulting OID to git diff.
  stdout: exactly ONE line, `<tier> <reason>` (tier in {light,standard,full}).
  stderr: all WARN/diagnostic lines (fail-safe warnings) — NEVER stdout.
  exit:   0 on any successful classification (incl. fail-safe standard);
          2 on usage error (unknown flag, or --file with no path).
