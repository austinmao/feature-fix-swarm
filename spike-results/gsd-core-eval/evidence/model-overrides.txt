## Method (corrected re-run 2026-07-05T02:01Z)

Prior run (INCONCLUSIVE) died on an account session-limit before any subagent
spawned, and used the wrong seeder command (`/gsd-add-phase` — unknown; correct
is `/gsd-phase`). Corrected harness (`$SB/run-overrides2.sh`):

1. Seed phase 2 with `/gsd-phase` (verified exists: `.claude/commands/gsd-phase.md`).
2. Per override: wipe phase-2 plan files, set
   `config.model_overrides.gsd-planner = <model>`, SNAPSHOT the existing
   `*/subagents/agent-*.jsonl` set, run `/gsd-plan-phase 2` under
   `--strict-mcp-config --mcp-config '{"mcpServers":{}}'` (env-fit requirement),
   then DIFF the subagent-transcript set to isolate the NEW gsd-planner spawn and
   grep its `message.model`.
3. Observation = subagent transcript `message.model` (config contents do NOT
   count as observation, per plan). Parent-last `subagent_type` confirmed
   `gsd-planner` for every row.

The drive process hit the 300s timeout each time (`drive-exit=124`) — expected,
`/gsd-plan-phase` is long — but the gsd-planner subagent spawned and emitted its
model-attributed turns BEFORE the timeout, which is the load-bearing observation.
