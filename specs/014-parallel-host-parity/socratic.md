Validate run/workspace/objective exclusivity in a short transaction; a nonce and process-start identity accompany monotonically increasing fencing generations. ## Top risks

1. **Already observed staging escape:** Upstream Codex staging wrote shared skills outside the chosen configuration root. Exact old bytes are unavailable for 60 files; maintain guarded copies and reconcile only with verified owned 1.13 output. A profile VERSION file is insufficient evidence of installation consistency.
2. **Duplicate execution during launch recovery:** Intent/acknowledgement gaps, paused owners or PID reuse can create two writers. Exercise deterministic process barriers and fencing rejection, not sleep-based probability tests.
3. **False host parity:** Permitting Codex0.154 in a version check or finding installed hooks proves neither runtime policy nor discovery. Actual authenticated deny/allow canaries and immutable tuple verification are mandatory.
4. **Unsafe ownership migration:** Live legacy leases cannot be rewritten or simulated. Install readers, preserve active owners, activate writers only after demonstrable handoff, and retain restartable journals plus rollback evidence.
5. **Partial rollout disguised by a green subset:** Current Python/Bats failures and coverage deficit remain unresolved; OpenClaw, Ubuntu, real-host overlap and denial tests remain required even if unit tests pass.
6. **Customization loss:** External symlinks, separate npm ownership, dirty gstack and OpenClaw fork adaptations evade shallow manifests. Resolve actual ownership and hash every affected surface before any replacement.
